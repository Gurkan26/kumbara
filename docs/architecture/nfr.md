# Non-Functional Requirements (NFRs)

This document formalizes the non-functional requirements and quality attributes for the **Kumbara** educational fintech platform.

## Quality Attributes Table

| Quality Attribute | Target | How Achieved | Verification |
|---|---|---|---|
| **Financial Integrity & Correctness** | Zero balance drift; exact double-entry balance sum ($\sum \text{Debit} + \sum \text{Credit} = 0$) at all times. No lost or phantom funds. | Double-entry append-only ledger entries executed within a single database transaction. Strictly forbidden `UPDATE`/`DELETE` operations. Reversal entries for error correction. Domain `Money` value object backed by `decimal(19,4)`. | Unit tests asserting double-entry conservation law; automated ledger reconciliation jobs verifying $\sum \text{Entries} = \text{CachedBalance}$. |
| **Data Consistency** | Strong consistency within service boundaries; eventual consistency across microservice workflows (< 2 seconds under normal conditions). | ACID transactions with optimistic locking (`rowversion`) inside Ledger and Wallet. Transactional Outbox pattern paired with MassTransit Sagas across services. | Integration test asserting eventual saga completion and state convergence after simulated network jitter. |
| **Idempotency** | 100% duplicate protection for mutating API calls and message consumers. Retried requests must never create duplicate entries. | Mandatory `Idempotency-Key` HTTP header handled by ASP.NET Core middleware with 24-hour response caching in Redis/DB; MassTransit inbox deduplication (`InboxState`) for integration events. | Automated integration tests executing the same HTTP POST transfer request 10 times concurrently and verifying exactly one transfer executed. |
| **Availability** | 99.9% uptime during operational testing; graceful degradation during isolated service outages. | Decentralized microservice architecture. If Risk service is temporarily offline, saga halts or queues requests rather than losing state. Health checks (`/healthz`) on all services exposed to gateway. | Chaos testing / container kill simulations (e.g. killing Risk service during transfer saga) to verify safe resumption upon restart. |
| **Performance & Latency** | P95 API response time < 150ms for read queries; < 300ms for initiating asynchronous transfer sagas. | YARP lightweight reverse proxy routing; Redis caching for frequently accessed account balances; non-blocking asynchronous processing with EF Core and MassTransit. | k6 / Bombardier load testing scripts measuring latency distribution under 200 concurrent simulated users. |
| **Security & Authentication** | Zero unauthorized access to protected endpoints; strict token validation; tamper-proof credentials. | OAuth 2.0 / OpenID Connect authorization server powered by OpenIddict; ASP.NET Core JWT bearer authentication; BCrypt/Argon2 password hashing; principle of least privilege in SQL access. | Automated security unit tests verifying 401/403 responses on unauthenticated or expired token requests; static analysis scanning. |
| **Auditability & Traceability** | 100% of financial modifications and saga state transitions traceable with timestamps and actor identities. | Immutable append-only `LedgerEntry` records; correlation IDs (`X-Correlation-Id`) propagated from Gateway through HTTP headers to MassTransit message headers and Serilog context. | End-to-end tracing audit verifying a transfer's log trajectory across YARP, Transfer, Risk, and Ledger via a single correlation ID in Seq. |
| **Fault Tolerance & Resilience** | Zero data loss on message broker or database transient failures. | Transactional outbox keeps unpublished events safe on disk during RabbitMQ outages; exponential backoff retries with dead-letter queue (DLQ) routing in MassTransit. | Broker failure injection test: disable RabbitMQ, perform transfers, restore RabbitMQ, and verify all outbox messages publish cleanly. |
| **Maintainability & Modularity** | Clean Architecture separation; zero forbidden dependencies across domain boundaries. | Strict Clean Architecture project layers (Domain, Application, Infrastructure, Api); database-per-service isolation; Shared BuildingBlocks for common contracts. | Automated architecture fitness tests in `Kumbara.Architecture.Tests` checking layer dependencies (e.g. Domain references nothing). |
| **Observability** | Real-time visibility into microservice health, throughput, errors, and saga durations. | Serilog structured JSON logging directed to Seq; distributed correlation IDs; standard health check endpoints (`/health/live`, `/health/ready`). | Seq log queries validating that error rates, warnings, and latency metrics are populated during execution runs. |
